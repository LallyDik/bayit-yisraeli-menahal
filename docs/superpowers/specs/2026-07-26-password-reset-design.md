# שחזור סיסמה — עיצוב

תאריך: 2026-07-26

## מטרה

לאפשר למשתמש ששכח את סיסמתו לאפס אותה בעצמו: קישור "שכחתי סיסמה" במסך
ההתחברות, מייל איפוס מ־Supabase, ודף לקביעת סיסמה חדשה. כיום אין אפשרות כזו,
ובמערכת יש ~40 משתמשים אמיתיים.

## זרימה

```
מסך התחברות ──"שכחתי סיסמה"──► טופס בקשה (מייל)
                                     │ resetPasswordForEmail(email, redirectTo=/reset-password)
                                     ▼
                          הודעה ניטרלית ("אם קיים חשבון...")
                                     │
                        Supabase שולח מייל בעברית ◄── תבנית מותאמת בדשבורד
                                     │  המשתמש לוחץ על הקישור
                                     ▼
              /reset-password  ◄── Supabase מזהה טוקן ב־URL, פותח session זמני
                                     │  (אירוע PASSWORD_RECOVERY)
                                     │  טופס: סיסמה חדשה + אימות
                                     │  updateUser({ password })
                                     ▼
                          הצלחה → מעבר ל־"/" (מחובר)
```

## רכיבים וקבצים

| קובץ | שינוי | אחריות |
|---|---|---|
| `src/hooks/useAuth.ts` | הוספת `requestPasswordReset` ו־`updatePassword` ל־context ול־provider | עטיפת קריאות Supabase, באותו סגנון של `signIn`/`signUp` |
| `src/components/Auth.tsx` | הוספת מצב "איפוס" + קישור "שכחתי סיסמה" | טופס בקשת איפוס במסך ההתחברות |
| `src/pages/ResetPassword.tsx` | **חדש** | דף קביעת סיסמה חדשה |
| `src/App.tsx` | ראוט חדש `/reset-password` מעל ה־catch-all | ניתוב |

### `useAuth`

```ts
requestPasswordReset: (email: string) => Promise<void>;
updatePassword: (password: string) => Promise<void>;
```

- `requestPasswordReset`: `supabase.auth.resetPasswordForEmail(email, { redirectTo: `${window.location.origin}/reset-password` })`. שגיאה נזרקת רק על תקלת רשת/קצב, לא על "מייל לא קיים".
- `updatePassword`: `supabase.auth.updateUser({ password })`.

### `Auth.tsx`

מצב שלישי לצד login/signup: `mode: 'login' | 'signup' | 'reset'`. קישור "שכחתי סיסמה"
מוצג במצב login. מצב reset מציג שדה מייל + כפתור "שליחת קישור לאיפוס" + קישור
"חזרה להתחברות". אחרי שליחה — **תמיד** הודעת הצלחה ניטרלית:
> "אם קיים חשבון עם המייל הזה, שלחנו אליו קישור לאיפוס."

זו החלטת אבטחה: לא לחשוף אילו כתובות רשומות (enumeration).

### `ResetPassword.tsx`

- טופס: סיסמה חדשה + אימות סיסמה, עם כפתור הצג/הסתר (כמו ב־Auth).
- שליחה → `updatePassword` → toast הצלחה → `navigate('/')`.
- **קישור פג־תוקף/לא תקין:** אם אין session מסוג recovery (המשתמש הגיע לדף ישירות
  או שהקישור פג), מציג הסבר + קישור לחזור ולבקש איפוס חדש.
- זיהוי מצב ה־recovery: הדף נשען על ה־session ש־Supabase פותח מה־URL. הוא בודק
  `supabase.auth.getSession()` ומאזין ל־`onAuthStateChange` לאירוע `PASSWORD_RECOVERY`.

## טיפול בשגיאות

| מצב | התנהגות |
|---|---|
| מייל לא קיים | הודעה ניטרלית זהה (ללא הדלפה) |
| סיסמה < 6 תווים | חסימה בטופס + הודעה |
| סיסמה ואימות לא תואמים | חסימה בטופס + הודעה |
| קישור פג/לא תקין | הודעה + קישור לבקשה חדשה |
| תקלת רשת/קצב | toast שגיאה, הטופס נשאר פתוח |

## הגדרות Supabase (בדשבורד — מבוצע ידנית)

1. **Redirect URLs** — כבר כולל `https://nihulschirut.com/**`, מכסה את `/reset-password`. ✅
2. **תבנית מייל "Reset Password"** — התאמה לעברית (הטקסט יסופק בתוכנית/בצ'אט).

## מקרי קצה

- **משתמש Google ללא סיסמה** — בקשת איפוס תשלח מייל שמאפשר לקבוע סיסמה ראשונה; לאחר
  מכן יוכל להתחבר גם עם מייל. תקין ורצוי.
- **משתמש כבר מחובר** שמגיע ל־`/reset-password` — הדף מציג את הטופס בכל מקרה (ראוט ייעודי).

## בדיקות

ולידציית הסיסמה היא inline בטופס (`minLength={6}` על השדות + בדיקת התאמה),
בדיוק כמו ב־`Auth.tsx` הקיים — אין util נפרד. אין תשתית לבדיקות רכיבי React
בריפו (node env, ללא jsdom), ולכן לפיצ'ר הזה אין בדיקת יחידה, כמו ל־`Auth.tsx`.
אימות: `npx tsc --noEmit`, `npm run build`, ובדיקה ידנית מקצה לקצה (בקשה → מייל →
סיסמה חדשה → כניסה).

## מחוץ לתחום

- אימות דו־שלבי (2FA)
- מדיניות סיסמאות מורכבת מעבר למינימום 6 תווים
- שינוי סיסמה מתוך המערכת (למשתמש מחובר) — פיצ'ר נפרד אם יידרש
